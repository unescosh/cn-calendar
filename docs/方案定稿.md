# 桌面日历 · 方案定稿

定稿日期：2026-11-09
项目根目录：`C:/Users/unesc/Downloads/日历`

## 一、要解决的问题

现用「优效日历」的日历内容（农历、节气、烈士纪念日等我国特色节日）符合需求，
但会员功能、备忘录功能属于冗余，且频繁弹出会员广告。

本项目的目标不是"做一个更全的日历"，而是**把日历内容从商业客户端里剥出来**：

- 程序本体完全离线可用，无账号、无登录、无云同步
- 不做会员、不做内购、不做备忘录、不做待办、不做广告位（代码里不留这几类模块）
- 联网只做两件事：静默同步年度调休数据、核对日期与节日是否一致；
  失败即回退内置快照，永不弹窗、永不提示升级

## 三、技术栈裁决依据

### 为什么是 Flutter 3.22 + Rust

1. 与既有 inksync 项目同栈，Flutter 3.22 的 `analyze` info 级误报、GitHub API 提交旁路等坑已踩过，可直接复用经验。
2. 统信 UOS V20 为 Debian 10 系、glibc 2.28。Flutter 官方 Linux 桌面**构建**环境要求 Debian 11+ / Ubuntu 20.04+，但**运行**编译产物只需 glibc ≥ 2.28 ＋ `libgtk-3-0` ＋ `libgl1`。缺口仅在构建侧，用较新的 CI 容器补齐即可，不影响目标机。
3. Rust 核心纯 `std`、无外部 crate，交叉编译与老系统部署成本最低，且能在本机直接跑单元测试。

### 明确的技术风险（须由 CI ＋ UOS 实机验证，不得靠推测下结论）

- **图形栈（2026-11-09 16:37 实机验证通过，风险关闭）**：UOS 20 的 Glenfly Arise1020
  硬件加速正常（OpenGL 4.5 / Mesa 25.00.58），Debian 10 重编的 Flutter bundle 在 X11
  里正常弹窗、EGL/GL 初始化无报错、翻月与窗口缩放均正常。此前担心的 EGL/GL 盲区已消除，
  不需要软件渲染回退参数。
- **非 x86 架构**：Flutter 官方引擎只有 x86_64 / arm64 产物。若后续确需 loongarch64 / sw64，须改用 Qt 5.15（UOS 原生 DTK 底子），届时 UI 层需重写，故核心逻辑刻意与 UI 解耦、独立成 crate。
- **透明置底挂件**：Flutter 无原生 API，需平台通道分别实现（Windows 用 Win32 分层窗口 /
  `WS_EX_LAYERED` 并置底，UOS 用 X11 `_NET_WM_STATE_BELOW` + ARGB 视觉）。
  必须置底而非置顶，否则会挡住全屏会议/播放器；还要处理 `Win+D` 显示桌面。
  这是 P2，方案见 `docs/P2桌面形态方案.md`，不阻塞 P0/P1。
- **本机工具链**：`rustc 1.98.0` 可用（需直调 `rustup which rustc` 的真实路径，PATH 上的 shim 输出被吞）；`flutter`/`dart`/`cmake`/`ninja`/`pkg-config`/`gcc` 均不可用。因此 Dart 代码的编译结论只能来自 CI。

## 四、架构分层

```
① 数据源      holiday-cn 年度调休 JSON ＋ 内置 L1/L2/L3 静态数据   [唯一需联网]
② 静默更新器  校验和/版本比对 · 本地快照兜底 · 多 CDN · 跨年提前拉取  [无提示无弹窗]
③ 计算核心    Rust，纯离线：公历/农历/节气/纪念日/调休合并           [可单测]
④ 界面壳      Flutter：桌面挂件 + 托盘月历 + 节日角标                 [无商业模块]
⑤ 双端打包    Win10 exe ＋ UOS deb/AppImage                        [CI 构建]
```

关键原则：**③④⑤ 完全离线**。断网、内网、涉密机上照样显示烈士纪念日、农历与节气；
联网只影响"今年哪天补班"。

## 五、节日数据四层

| 层 | 内容 | 来源 | 联网 |
|---|---|---|---|
| L1 固定公历 | 烈士纪念日 9/30、抗战胜利纪念日 9/3、国家公祭日 12/13、国家宪法日 12/4（四者均由全国人大常委会 2014 年决定设立）等 | 内置静态表 `data/memorial-days.json` | 否 |
| L2 规则型 | 全民国防教育日（9 月第三个周六）、全国助残日（5 月第三个周日）、文化和自然遗产日（6 月第二个周六）、中国农民丰收节（秋分） | `data/rule-days.json` ＋ 本地算法 | 否 |
| L3 农历节气 | 春节/元宵/端午/七夕/中元/中秋/重阳/腊八/除夕、二十四节气、干支生肖 | `data/lunar-table.json`（由 lunar-javascript 1.7.0 预生成） | 否 |
| L4 年度调休 | 国务院办公厅次年放假安排与补班日 | `holiday-cn`（GitHub Actions 每日抓 gov.cn 公告） | **是** |

合并优先级（写死并单测锁住）：**补班日 > 法定休 > 周末 > 工作日**。
调休无法由农历推算，只能读年度表，这也是唯一需要自动更新的部分。

## 五之二、联网核对（用户追加要求）

用户明确：电脑允许联网，但日历最重要的是精确，日期、星期等数据必须准确，
因此要在本地计算的基础上联网同步确认、核对日期与节日是否一致。

**裁决：本地是基础，联网是校验，不让上游错误污染已通过测试的本地计算。**

| 层 | 联网能做什么 |
|---|---|
| L1 / L2 / L3 | 只核对存在性与结果，**无权改写** |
| L4 | 允许更新（本地算不出来），但更新前先出差异报告 |

四项核对（详见 `docs/数据核对规范.md`）：

1. **HTTP `Date` 响应头**作为权威日期/星期基准（RFC 7231）。任何 HTTP 服务器都返回该头，
   不需要专用时间 API，也不需要信任响应内容。三方比对：远端星期 ↔ 本机 UTC 星期 ↔
   `cn_cal_cli day` 的 `weekday` 字段。
2. **本地算法自洽**：`cn_cal_cli verify weekday` 逐日验证 2020–2050 共 11323 天的
   公历往返与星期循环，断网也跑。
3. **L4 快照差异**：`cn_cal_cli verify holiday` 逐条比对内置快照与上游，
   差异分为 `added` / `missing` / `changed`。
4. **节日抽样**：四个国家级纪念日必须出现；上游每个法定休日期本地须判 `rest=true`，
   每个补班日须判 `makeup=true && workday=true`。

差异一律写 `verify-report.json` 并在界面可查，命令行发现差异退出码 2 让 CI 变红；
断网记 `offline` 且退出码 0。**绝不因核对结果去改写 `data/` 下的静态数据**——那是源码，
改动必须走测试与版本控制。

本机实跑（2026-11-09）：3 个 HTTP 源 Date 头给出 2026-11-09 周一，与本机及本地算法一致；
11323 天星期连续一致；2025/2026/2027 调休 33/39/34 条与上游零差异；
106 条调休日 + 12 个国家级纪念日抽样零问题，状态 `consistent`。

## 七、验收口径

- 任何"能编过 / 能跑"的结论，Rust 部分以本机 `cargo test` 为准，Flutter 与打包部分以 CI run 为准。
- 不在本机 UI 上做"看起来没问题"的推断。
- 数据层改动必须同时更新 `tools/verify_data.py` 校验规则与 `core/tests` 中的锚点断言。
- 农历/节气改动必须额外通过 `tools/cross_check_lunar.js` 双实现逐日交叉核对
  （11299 天 × 7 字段），仅有生成器复现性校验不足以证明查表逻辑正确。
- 本机已实跑的精确性证据：34 个 Rust 测试、2183 项数据校验、11323 天星期连续、
  79093 次双实现比对、106 条调休 + 12 个国家级纪念日抽样，全部零差异。
