# 日历数据规范 v1

适用范围：`cn_cal_core` 计算核心与所有上层界面。本规范是数据契约，改字段须同步改 `tools/verify_data.py` 与 `core/tests`。

## 文件清单

| 文件 | 层 | 生成方式 | 联网 |
|---|---|---|---|
| `data/memorial-days.json` | L1 | 人工维护（法律/国务院规定，极少变动） | 否 |
| `data/rule-days.json` | L2 + L3 节日规则 | 人工维护 | 否 |
| `data/lunar-table.json` | L3 基础数据 | `tools/gen_lunar_table.js` 由 lunar-javascript 1.7.0 预生成 | 否 |
| `data/festival-anchors.json` | L4 节日正日映射 | 人工维护（法定假期名 → 节日当天） | 否 |
| `data/holiday-YYYY.json` | L4 | 上游 `holiday-cn`，内置快照；运行时由静默更新器覆盖 | 是 |
| `<缓存>/holiday-YYYY.json` | L4 | 联网核对后写入的权威副本，核心启动时读取覆盖 | 是 |
| `<缓存>/verify-report.json` | — | 核对报告，契约见 `docs/数据核对规范.md` | 是 |
| `tools/vendor/lunar-javascript-1.7.0.js` | — | 上游 npm 包（仅生成期使用，不进入运行时） | 否 |

## L1：固定公历纪念日

```json
{ "meta": { "layer": "L1", "version": 1 },
  "days": [ { "date": "09-30", "name": "烈士纪念日", "kind": "国家级纪念日", "law": "..." } ] }
```

- `date`：固定 `MM-DD`，不含年份；每年自动套用。
- `kind`：`节日` / `国家级纪念日` / `纪念日` / `主题日`。UI 可据此给角标分级，国家级纪念日单独着色。
- `law`：可选，仅对有法律/决定依据的条目填写，用于详情面板展示来源。

## L2：规则型日子

```json
{ "weekday_rules": [ { "name": "全民国防教育日", "month": 9, "weekday": 6, "nth": 3, "kind": "纪念日" } ],
  "solar_term_rules": [ { "name": "中国农民丰收节", "term": "秋分", "kind": "节日" } ] }
```

- `weekday`：`0`=周日 … `6`=周六；`nth` 表示该月第 n 个该星期几。
- `solar_term_rules`：命中当年对应节气日期。

## L3：农历与节气

`lunar_festivals`（放 `rule-days.json`）：

```json
{ "lunar_festivals": [ { "name": "春节", "month": 1, "day": 1, "kind": "节日" },
                       { "name": "除夕", "month": 12, "day": 0, "kind": "节日" } ] }
```

- `day: 0` 表示"该月最后一天"（腊月大小年不定，用于除夕）。
- 闰月不触发节日（如闰八月十五不算中秋）。
- v2 传统节日清单：春节、破五、元宵节、龙抬头、上巳节、端午节、七夕节、中元节、
  中秋节、重阳节、寒衣节、下元节、腊八节、除夕；节气型另含清明节、
  中国农民丰收节、冬至节。
- **未收录**：小年（北方腊月廿三 / 南方腊月廿四，日期有地域差异）、
  寒食节（清明前一日，规则引擎暂不支持相对节气偏移）、宗教性与
  地方性强、日期不唯一的日子。宁可少收也不给不精确的日期。

`lunar-table.json` 年度记录：

```json
{ "y": 2026, "spring": "2026-02-17", "ganzhi": "丙午", "shengxiao": "马",
  "months": [ { "m": 1, "leap": false, "days": 30, "start": "2026-02-17" } ],
  "jieqi": [ { "name": "小寒", "date": "01-05" } ] }
```

- `months`：本农历年正月→腊月（12 或 13 项），`start` 为该月初一的公历日期。
- 定位算法：给定公历日 D，找到最后一个 `start <= D` 的月，农历日 = `D - start + 1`；月边界由 `days` 校验。
- `jieqi`：固定 24 条，按节气顺序，`date` 为 `MM-DD`。
- 覆盖范围见 `meta.range`，但**年份范围不等于日期覆盖范围**：例如 2020 年春节在 1/25，
  2020-01-01～01-24 查不到农历。精确边界由 `Calendar::lunar_covered_range()` 返回
  （本次数据为 `2020-01-25` ～ `2051-02-11`，左闭右开）。
- 范围外**优雅降级**：仍显示公历、L1、L2、L4，仅不显示农历/节气，不得报错或空白。

## L4：年度调休（上游格式，不做转换）

```json
{ "year": 2026, "papers": ["https://www.gov.cn/..."],
  "days": [ { "name": "春节", "date": "2026-02-17", "isOffDay": true } ] }
```

- `isOffDay: true` = 法定休息日；`false` = 调休上班日（补班）。
- 保留上游原始文件名与字段，便于直接替换、比对与审计。
- 内置快照：`2025` / `2026` / `2027` 三年真实数据（2027 年公告已发布）。

### 上游 `name` 的语义与「节日正日」

上游 `days[].name` 表示**该日属于哪个假期的调休安排**，会在整段放假区间里重复。
例如 2026 年 10/1—10/7 每天都写 `国庆节`，但只有 10/1 是国庆节；
2025 年国庆中秋连休则统一写成 `国庆节、中秋节`。

因此 `data/festival-anchors.json` 为每个假期名登记「节日正日」：

```json
{ "name": "国庆节", "type": "solar", "month": 10, "day": 1 }
{ "name": "春节", "type": "lunar", "month": 1, "day": 1 }
{ "name": "清明节", "type": "solar_term", "term": "清明" }
{ "name": "国庆节、中秋节", "type": "compound", "parts": ["国庆节", "中秋节"] }
```

- `solar`：固定公历月日；`lunar`：农历月日（闰月不算）；`solar_term`：节气当天。
- `compound`：连休合并假期，子项必须指向已登记的基础锚点，命中任一子项即为正日。
- **只有正日**才允许在 `labels` 里出现该节名；假期其余日期照样是法定休
  （`holiday_name` 保留，供界面画假期配色与「休」角标），但不带节名标签。
- 未登记的假期名一律不标节名，宁可少标也不能把整段假期叫成同一个节。
- `tools/verify_data.py` 会检查所有内置 L4 假期名都已登记正日；
  `tools/verify_online.py` 会核对正日确实带上了节名标签。新增假期必须同步改这张表。

## 输出：DayInfo

```json
{ "date": "2026-09-30", "weekday": 3, "workday": true, "rest": false,
  "labels": [ { "name": "烈士纪念日", "kind": "国家级纪念日", "layer": "L1" } ],
  "lunar": { "month": 8, "day": 20, "leap": false, "month_days": 29, "text": "八月二十" },
  "jieqi": null, "ganzhi": "丙午", "shengxiao": "马",
  "holiday_name": null, "makeup": false, "festival_day": false }
```

- `labels` 按 layer 顺序 L1 → L2 → L3 → L4 稳定排序；UI 最多露两条，
  显示优先级见下节「CLI 输出编码与同格标签显示」。
- `holiday_name` / `makeup` 是 L4 的独立输出，供 UI 画「休 / 班」角标，不重复塞进 labels。
- `festival_day` = 该日是某个法定假期的节日正日。UI 据此加强调（日期数字加粗、
  详情里写「节日正日」）；旧版客户端读到缺省值按 `false` 处理，保持前后兼容。
- L4 的法定假名称与已有标签同名、或互为子串时（如「清明」vs「清明节」）不重复出角标；
  补班日统一以「补班」标签表示；假期内非正日不写节名标签。

## CLI 输出编码与同格标签显示

**编码契约（Win10 实机踩坑，必须锁死）**：`cn_cal_cli` 的 stdout / stderr 固定输出
UTF-8。中文 Windows 下 Dart 的 `Process.run` 默认按 `systemEncoding`（GBK / CP936）
解码子进程输出，「丙午」「寒衣节」等多字节中文会变成非法字符，`jsonDecode` 随即
抛 `FormatException`，界面白屏。因此两个调用点（`CalendarBridge.month` 与
`VerifyService._cliJson`）都必须显式写：

```dart
stdoutEncoding: utf8,
stderrEncoding: utf8,
```

`CalendarBridge.parseMonth(String)` 是整月 JSON 的解析入口；Dart 单测把
「UTF-8 字节流 → 中文标签 / 干支 / 生肖一个字不丢」与「两处 `Process.run`
都带显式 utf8」列为回归项。P2 换 FFI 后 JSON 契约不变，编码口径仍需遵守。

**同格标签显示**：格子最多显示两个标签（换行分隔，界面 `maxLines: 2`），
排序优先级 `节日 / 国家级纪念日 > 法定假 / 调休 > 纪念日 > 主题日`，取前两个。
UOS 第 6 步实机发现 `2026-11-09` 的「寒衣节」（L3 节日）被同日 L1
「全国消防日」整个挤进详情弹窗；数据本身没丢，但月历上一眼看不到。
没有标签时退回节气，再退回农历日。

## 合并优先级（必须单测覆盖）

```
1. L4 补班日 (isOffDay=false)  → workday=true，压过周末
2. L4 法定休 (isOffDay=true)   → rest=true，压过工作日
3. 周末                        → rest=true
4. 其余                        → workday=true
```

同一天可同时挂多个 label（例如 10-01 既是国庆节也是法定休），label 与 workday/rest 判定互不干扰。

## 自动更新契约

- 拉取地址（按序尝试，任一成功即止）：
  1. `https://cdn.jsdelivr.net/gh/NateScarlet/holiday-cn@master/{year}.json`
  2. `https://raw.githubusercontent.com/NateScarlet/holiday-cn/master/{year}.json`
  3. 可配置的镜像/内网地址
- 时机：启动时静默检查；此后每 7 天；每年 11 月起额外尝试拉取 `year+1`。
- 校验：`year` 字段必须匹配请求年份；`days` 非空；每条 `date` 合法且属于该年；重复日期合并去重；校验和写入本地元数据。
- 回退：任一环节失败都**静默**使用内置快照或上次成功缓存，不弹窗、不写日志到界面、不阻塞启动。
- 无网络环境下全部功能（除当年新增调休）照常工作。
- **核对**：写入缓存前后都要与内置快照比对并出报告，差异分级与报告格式见
  `docs/数据核对规范.md`。联网数据**只覆盖 L4**，L1/L2/L3 一律以本地计算为准。
- **闭环**：缓存目录通过 `CN_CAL_HOLIDAY_DIR` 传给 `cn_cal_cli`，启动时按 `holiday-YYYY.json`
  覆盖同名年份；校验失败的文件静默跳过，保留内置快照。下载了却没人读不算完成更新。

## 不做的事

会员、账号、云同步、备忘录、待办、订阅、遥测上报、广告位、付费解锁。
这些不在数据契约里，也不允许以"预留字段"形式出现。
